# ADR-003：多用户与账号认证

日期：2026-10-11 ｜ 状态：已接受

## 背景

v1 是单用户单机：所有对局与档案馆硬编码 `user_id=1`，管理面用一条共享口令（`ADMIN_PASSWORD`）。
要开放给多人游玩（每个玩家有自己的对局、档案馆、续局进度），需要账号体系与管理员运维入口。

## 决策

延续 ADR-001 的零依赖承诺，认证全部用 Node 内建实现：

| 议题 | 决策 | 理由 |
|---|---|---|
| 口令存储 | `node:crypto` scrypt（N=16384, r=8, p=1）+ 16 字节随机盐，自描述格式 `scrypt$N$r$p$salt$hash` | 无需 bcrypt/argon2 依赖；参数内嵌便于将来升级参数平滑迁移；`timingSafeEqual` 常量时间比较 |
| 会话 | 进程内存 token 表 + HttpOnly Cookie（`SameSite=Lax`）；API/测试可用 `Authorization: Bearer` | 单进程部署，重启即全员重登（可接受）；HttpOnly 防 XSS 窃取；Lax + JSON content-type 双保险防 CSRF |
| 注册 | 开放注册；用户名 2–24 位 unicode 字母/数字/`_`/`-`，口令 ≥6 位；注册/登录共用输入限流 | 游戏账号的威胁模型；限流挡批量注册撞库 |
| 管理员 | `ADMIN_USERNAME`/`ADMIN_PASSWORD` 环境变量注入；**首次用该凭据登录时创建 `is_admin=1` 用户记录**；此后环境凭据仍为最高权（同名账号口令不符时以环境凭据提权/改哈希） | 运营者持有环境变量即持有管理员身份；无需种子脚本或 CLI；换口令=改环境变量再登录一次 |
| 保留名 | 注册拒绝 `ADMIN_USERNAME`，避免管理员名被抢注后凭据语义混乱 | 环境凭据本可夺回，但拒绝更干净 |
| 数据隔离 | `run` / `archive_entry` 按会话用户读写；越权访问一律 404（不泄露存在性）；管理员可读任意对局（回放/运维） | 最小权限；404 防枚举 |
| 旧数据 | 迁移 003 把单用户时代 `user_id=1` 的行无主化（置 NULL）——不落进任何新用户名下，仅管理员可见 | 第一个注册者恰好分到 id=1，不能让他继承旧数据 |

## 后果

- 浏览器全流程走 Cookie（landing 登录 → `/app` 游戏），前端不再持有 token；测试与脚本走 Bearer。
- 旧 `/api/admin/login`（共享口令）移除，管理面统一走账号会话 + `is_admin`。
- 会话不持久化：重启重登。若将来要多实例部署，把 token 表换成 SQLite 表即可（接口不变）。
- 登录失败对"用户不存在/口令错误"返回同一文案，且都执行一次同代价哈希（预生成的 DUMMY_HASH），抹平时序差。
