# ADR-004：决断意志交互模型（v2）

> 日期：2026-10-11 · 状态：已落地（168 测试全绿 + sim 门禁通过）

## 背景

v1 的玩家输入以自由文本为主通道：白天每人 3 AP 的内务（喂饭×4、做饭、治疗、守夜指派）
全要逐条打字，一天 8-15 次输入里约七成是模式化重复劳动；直读语法是一张隐藏手册，
学习成本集中在"记住能说什么"。模拟机器人（bots.js）的存在证明了一件事：
**最优日常是算法化的——能被写成算法的，就不该要求玩家手打。**

## 决策

交互模型改为「决断意志」（GDD §16 待定问题 3 的既有措辞）：

1. **玩家输入只有两种**：自由文本（想法/规矩/具体安排）+ 决策卡（选择题）。
2. **日常委托落地**（内核设计 §5.3 Z 系）：`auto_day` / `auto_night` 宏意图由内核管家
   （`core/src/delegate.js`）惰性展开为原子意图，与手输意图走**同一条 resolve 管线**——
   同一校验、同一守恒、同一事件溯源。自动化没有第二条状态通道。
3. **策略意图**（`policy`）："省着吃"等话语沉淀为持久规矩，经 FLAG 事件记账，
   fold 回放天然兼容；旧存档由 `policyOf` 兜底默认值，无需迁移。
4. **归因**：管家执行的意图带 `delegated` 标记，进 facts 与因果账条目——
   回忆录分得清"你下的令"与"你立的规矩"（责任始终归玩家）。
5. **决策点泛化**：黄昏方案卡（planDusk）、晨报问题卡（dawnProblems）、
   夜间岔路（planNightStep 的 stop：NPC 照面 / 警觉 / 火柴将尽）、交易一键成交
   （tradeDeals，保守地板估值保证必过价格带）。全部视图由状态现算，不入账。
6. **降级路径**：LLM 缺席时纯选择 + 大白话关键词同样可玩——LLM 从必需品降为增强。

## 口径变化

- 夜间 NPC「不打扰」与剧本落幕记 `npcState='ignored'/'greeted'`（不再重复停问）；
  夜间新增零槽动作 `ignore`/`push_on`（它们是选择，不是动作）。
- 黄昏指派解析修复：外出者不再被误标为守夜（parser.js）。
- 交易卡物品显示中文名（v1 直出内部 id 的存量 bug 顺带修复）。
- 交易建议按地板价估值并预留建造底线（木板 6 / 零件 4）——一键成交可能略显吃亏，
  想讨价还价的玩家仍可自由文本谈判。

## 平衡性

sim 新增 `delegate` 策略（用游戏内管家本人跑局，事件一律选首个零成本项，
商人到访时点一条建议成交——与真实玩家点卡同口径）。v1 实测（100 局）：
中位 35 天、活到停火 56%、文档中位 2——不低于均衡机器人（30 天 / 18%）。
差距主要来自夜间自动流不浪费火柴（bot 的卡住重试逻辑会烧槽）。
管家是"尽责的普通人"的底线由 sim 测试断言（中位 ≥15 天、存活率 ≥10%）。

## 未做（有意不做）

- 人物卡动作菜单、库存点选：与新模型相悖（玩家不该再点菜式操作）。
- 快速模式连跳多天（Z-05）：委托已把平淡日压缩到两次点击，暂缓。
- 指挥模式开关：等有硬核玩家反馈再说。
